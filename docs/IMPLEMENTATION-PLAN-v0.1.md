# 《灵农修仙》当前实现计划

## 1. 已落地的运行闭环

- 3 块灵田、作物生长、成熟收获和自动补种。
- 默认自动收获并补种；点击生长中的灵田减少成熟倒计时。
- 灵气库存倍率、法术消耗和灵气商店补给；灵田收获不再产生灵气。
- 灵田直接结算修为与灵石；不再通过炼丹或服丹获得修为。
- 境界突破、生产/修炼倍率、灵田解锁和寿元上限。
- 突破后的九九/六九/三九天劫，以及治疗丹、抗性丹、强化丹的商店库存和使用。
- 寿元按每秒流逝；归零进入大限并暂停生产，可续命或手动开启新局。
- 修为里程碑和境界奖励天赋点。
- 独立的图形天赋树：农道、丹道、灵根三条分支。
- 独立商店：长生丹、聚气玉、治疗丹、抗性丹、强化丹、悟道残卷和突破材料。
- 四季、限时事件、噬金虫、灵雨诀、庚金剑诀和守护灵阵。
- 自动修炼和按长期计数的一次性离线折算。
- 成就系统：19 项长期目标、成就点、自动解锁和成就面板；不改变主经济。
- 游戏内数值模拟面板：实时状态、维度矩阵、熟练度矩阵、突破材料校验、境界总表和全量核心矩阵。
- 突破流程最大化模拟：天赋点实时加点，灵石按寿元→突破材料/渡劫丹→聚气玉的顺序购买，并输出每阶段明细。
- JSON 存档，当前版本 16，保存累计获得天赋点、天劫进度和渡劫丹库存。

## 2. 模块边界

| 模块 | 责任 |
|---|---|
| `game_state.gd` | 保存运行状态，调用系统规则，提供所有 UI 操作入口 |
| `save_manager.gd` | 序列化、读取、默认值和离线差额结算 |
| `balance_config.gd` | 唯一玩法数值源：境界、天劫、渡劫丹、作物、灵田、天赋、商店、事件、自动化和操作参数 |
| `talent_tree.gd` | 天赋节点图规则、前置关系和效果汇总（数据读取 `BalanceConfig`） |
| `shop.gd` | 商品查询和购买规则（商品数据读取 `BalanceConfig`） |
| `automation.gd` | 在线自动修炼速率 |
| `multiplier_stack.gd` | 生产、修炼、成长等倍率的集中计算 |
| `simulation.gd` | 读取 GameState 与内部配置，统一计算真实收获和只读模拟报告/矩阵 |
| `achievement.gd` | 读取成就定义、计算进度、记录一次性解锁和成就点 |
| `field_panel.gd` | 种植、切换作物、点击加速、灵田槽位购买和灵田升档交互 |
| `talent_panel.gd` | 天赋树图形显示和解锁交互 |
| `shop_panel.gd` | 商店商品显示和购买交互 |
| `simulation_panel.gd` | 游戏内模拟参数、矩阵展示、JSON 导出 |
| `achievement_panel.gd` | 成就进度、分类目标和成就点展示 |

规则不写入按钮回调。面板只读取状态并调用 `GameState` 的明确方法。

## 3. 当前数值

- 作物默认成长时间：5 秒。
- 寿元流逝：每秒 0.5 年；四个境界默认一轮约 2 / 4 / 6.7 / 16.7 分钟。
- 灵气收获：每 100 点当前灵气 +10%，基础上限 ×3。
- 点击加速：基础每次减少 1 秒，农道天赋可以提高效果。
- 灵田槽位：第 2 块凡人基准价 100 灵石，第 3 块凡人基准价 500 灵石；实际价格随当前境界生产倍率缩放为炼气 300/1,500、筑基 800/4,000、金丹 2,000/10,000，不设境界购买门槛。
- 灵田升档：炼气/筑基/金丹分别开放灵/宝/仙田购买权限，费用 4,000/120,000/3,000,000 灵石；农道核心天赋下目标约 45~90 秒回本，未点农道时约 120~180 秒回本。
- 境界累计修为门槛：0、1,000、80,000、2,000,000；筑基→金丹阶段目标至少为炼气→筑基的两倍，避免后段塌缩。
- 灵田档位产出倍率：×1、×10、×100、×1,000。
- 突破天赋点：按境界索引 `[0,3,7,15]`。
- 天劫：基础九九 99 道；未用天赋点达到 10 点降为六九 69 道，达到 25 点降为三九 39 道；基础劫体 100、每道伤害 2。
- 渡劫丹：治疗丹 1,500 灵石恢复 30 劫体；抗性丹 2,000 灵石增加 10 道半伤抗性；强化丹 2,500 灵石让本次劫体上限 +50、伤害 ×0.8，每次渡劫限用 1 枚。
- 熟练度门槛：每种作物 10 / 50 / 150 / 400 次，四种作物合计 44 点天赋。
- 离线折算：按轮回、晋级、总收获计数计算，和离线时长无关；上限 7 点天赋，大限不结算。
- 成就：当前 19 项、49 成就点；成就状态跨大限和新局保留，完成记录不重复计点。
- 数值统一：所有可调玩法数值集中在 `BalanceConfig`，真实结算、游戏内模拟和 headless 探针共用它；其它模块不复制数值表。

数值修改后，应同时检查 README、GDD 和相关 headless 探针。

## 4. 验证流程

```bash
/opt/homebrew/bin/godot --headless --path . --editor --quit
/opt/homebrew/bin/godot --headless --path . --quit
/opt/homebrew/bin/godot --headless --path . --scene res://scenes/probes/field_balance_probe.tscn
git diff --check
```

手动冒烟流程：

1. 启动新游戏，确认默认是自动收获并补种。
2. 等待作物成熟，确认自动收获；切换手动后确认按钮收获 3 倍。
3. 增加灵气，确认 HUD 的收获倍率和实际产出同步变化。
4. 连续运行几秒，确认寿元按秒减少，种植不改变寿元。
5. 让寿元归零，确认自动种植、收获和自动修炼暂停。
6. 在商店购买长生丹，确认续命后生产恢复；或在修炼面板开始新局，确认天赋树保留。
7. 打开天赋树，确认连接线、节点状态、前置和费用正确。
8. 在商店兑换服气丹和境界材料，确认材料库存变化；再验证缺材料时突破按钮不可用。
9. 备齐服气丹后点击突破，确认只进入天劫、境界暂不增加；使用三类渡劫丹并完成天劫，确认境界、寿元和突破天赋点在成功后才更新。
10. 退出并重新启动，确认上述状态仍然存在，包括中途天劫进度和渡劫丹库存。
11. 打开“成就”，确认收获、境界、灵田、熟练度、新局和天赋节点会自动更新，重复刷新不重复发放成就点。
12. 打开“数值模拟”，切换实时状态、各维度矩阵、熟练度矩阵和全量核心矩阵，确认突破流程报告包含天劫时间且不消耗资源；确认可导出 `user://simulation_report.json`。

## 5. 后续迭代顺序

1. 用真实试玩数据校准灵气、寿元和天赋点的增长速度。
2. 为天赋节点增加更清晰的图标、连线高亮和选中详情。
3. 增加更多作物和突破材料，但保持 `GameState` 的统一结算入口。
4. 补充手柄焦点导航、窗口尺寸适配和无障碍文本。
5. 在玩法稳定后再处理 Steam 成就、云存档和正式发行构建。
