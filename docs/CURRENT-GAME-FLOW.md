# 当前可执行流程：增量化 v1.2

本文只记录当前代码已经执行的规则。

## 状态层

```text
RunState
  本世修为、灵石、体魄、神识、气血、目标、完成节点、寿元软墙
LineageState
  出生历史、道蕴、材料仓、宝箱信用、突破失败次数
LegacyState
  首次发现、防重复账本、法则、自动化蓝图、设置
```

轮回将 `RunState.discoveries` 写入 `LineageState.historical_realm_unlocks`，然后从新的历史复制出生快照。`LegacyState.lifetime_discoveries` 只用于图鉴和防重复，不满足路线前置。

## 连续生产

`RateEngine.calculate()` 根据作物 cohort 比例、灵田等级、灵土阶数、聚灵阵、历史/本世最高 `H`、道蕴和软墙效率，返回修为、灵石、体魄、神识和三档宝箱 work 的每秒速率。

作物只保留生产组合，不保存逐株成熟对象。作物周期只用于内容定义和 UI 说明，不是经济结算边界。

## 宝箱与材料

`TreasureBatchService` 将连续 work 除以箱级阈值后批量结算。每条掉落通道用 `BigCounter` 定点信用，保证小步推进和整批推进结果一致。普通、精良、稀有作物不会随机升箱。

当前路线激活后，新增修为的 1.5% 按材料权重写入目标信用；对应品阶箱批次出现时释放可取整部分。材料保存在 `MaterialLedger`，突破批次通过 escrow 结算。

## 突破与雷劫

`BreakthroughService` 先检查出生历史前置、累计修为、材料和路线内容开关，再按节点基础概率、失败次数和硬保底执行最多 9 次批次。失败只消耗主材需求的 5%，成功的金丹节点创建 pending 雷劫。

`TribulationService` 的接口只有锁定气血和固定伤害。突破成功不会提前增加金丹 `H`；只有气血严格大于总伤害后，节点才写入本世发现。

## 世界推进与轮回

`WorldSimulator` 只在以下边界重算：修为目标、720/900 秒软墙、自动购买、自动突破、气血安全线和轮回。900 秒后进入 `AWAITING_RESET`。零发现且道蕴增量不足 1 的轮回不会增加长期资源。

离线有效时间为前 8 小时全额、之后 16 小时按 50% 计算，上限 16 小时有效时间。已开启策略后可以跨多个领域边界推进；收据有 100 条内存上限。

自动策略还会在不超过 10 秒的批处理窗口内重新检查购买、材料和雷劫条件，避免整段离线时间把中途可执行动作推迟到结算末尾。若遇到未完成的手动决策，剩余有效时间写入 `offline_time_bank`；策略哈希改变前不会自动消费这段时间。

## 存档

Save v20 保存三层状态、策略哈希、离线时间银行、收据、独立随机流和命令记录。突破、雷劫、轮回和飞升等关键事务在临时文件校验成功后才揭示；失败会恢复内存快照。保存流程先写临时文件并重新读取校验，再替换旧文件并保留 `.bak`。v18/v19 只在加载时转换一次，不作为运行时第二套状态；迁移报告会列出映射、取消和未映射字段。
