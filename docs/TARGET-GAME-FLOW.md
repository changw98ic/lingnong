# 《灵农修仙》目标版增量玩法流程图

这份文档把最新提出的方向转成一套可落地的目标逻辑。它不是当前代码的描述，而是下一版玩法基线。

## 1. 目标结论

当前版本更像“教学型小循环”：内容少、倍率低、自动化比重高、重置成长已经被移除。目标版要改成：

```text
短循环：主动操作和生产线管理
中循环：配方、升级、技能和生产分支
长循环：转世/飞升、永久倍率、成就和更高境界
```

| 方向 | 目标版规则 |
|---|---|
| 内容规模 | 作物、丹药、材料、生产线、升级、技能和事件全部数据驱动，首期支持几十种，后续可扩展到上百种 |
| 指数增长 | 境界、转世、研究、灵田、生产线、套装、事件和技能分层相乘；转世次数直接推动永久倍率增长 |
| 主动操作 | 点击立即产生资源或充能，同时可以加速；支持批量收获、批量炼制和技能连招 |
| 重置成长 | 转世/飞升是核心循环；重置当前局资源，获得永久资源和永久倍率，再挑战更高境界 |
| 离线 | 不只结算自动修炼；按 `OFFLINE_EFFICIENCY` 结算所有已经配置的生产线，效率范围为 50%~100% |
| 成就目标 | 成就记录生产、突破、连招、收集和极限挑战，并提供永久奖励或新内容 |
| 成本决策 | 种子、材料、灵气、生产线槽位、批量操作和维护都有成本；玩家需要决定生产什么、何时停产、何时转世 |

## 2. 目标版总流程

```mermaid
flowchart TD
    A[启动游戏] --> B[读取永久进度、当前局进度和生产线配置]
    B --> C{存在离线时间?}
    C -- 否 --> D[进入当前局]
    C -- 是 --> E[按 OFFLINE_EFFICIENCY 结算全部生产线]
    E --> F[结算离线收获、加工、炼制、自动升级和成就]
    F --> G[写回离线摘要和新时间戳]
    G --> D

    D --> H[选择目标产出和生产线]
    H --> I{资源和生产条件足够?}
    I -- 否 --> J[出售、购买、调整配方或暂停生产线]
    J --> H
    I -- 是 --> K[启动生产线]

    K --> L[时间生产持续产出]
    L --> M[玩家点击：即时产出 + 加速 + 连招充能]
    M --> N{连招条件满足?}
    N -- 是 --> O[释放技能组合，短时间放大产出]
    N -- 否 --> P[保持生产]
    O --> P
    P --> Q[批量收获 / 批量炼制 / 批量出售]
    Q --> R[资源进入下一条生产线]
    R --> S[触发里程碑、成就、解锁和升级]
    S --> T{达到当前境界或转世条件?}
    T -- 否 --> L
    T -- 是 --> U{继续本局还是转世/飞升?}
    U -- 继续本局 --> V[使用当前资源购买更高阶内容]
    V --> L
    U -- 转世/飞升 --> W[结算本局贡献]
    W --> X[发放转世资源、成就奖励和永久倍率]
    X --> Y[清空本局易失状态]
    Y --> Z[进入更高挑战层]
    Z --> H

    L -. 任意状态变化 .-> AA[保存当前局和永久进度]
    AA --> L
```

## 3. 三层状态模型

目标版不能再把所有状态都堆在一个 `GameState` 里。要把“本局会清空的状态”和“转世后仍然保留的状态”拆开，避免重置逻辑继续变复杂。

```mermaid
flowchart LR
    A[PermanentState 永久状态]
    B[RunState 当前局状态]
    C[ContentRegistry 内容数据]
    D[SimulationEngine 结算引擎]
    E[UI 面板]
    F[SaveManager 存档]

    C --> D
    A --> D
    B --> D
    E --> D
    D --> B
    D --> A
    A --> E
    B --> E
    A --> F
    B --> F
    F --> A
    F --> B
```

### 3.1 当前局状态 `RunState`

- 当前境界、当前修为、当前寿元。
- 灵石、灵气、灵材、丹药和临时货币。
- 灵田槽位、灵田等级、种植中的作物和生产线库存。
- 当前生产线、当前配方、自动化开关和生产线维护状态。
- 临时 buff、事件、技能冷却、连招能量和本局成就进度。

### 3.2 永久状态 `PermanentState`

- 转世/飞升次数。
- 永久倍率、永久货币和永久研究点。
- 永久天赋树、研究树和解锁内容。
- 成就完成状态、收藏图鉴和最高境界记录。
- 已领取的永久里程碑奖励。

### 3.3 内容数据 `ContentRegistry`

所有内容都用数据表注册，不为每种作物或丹药单独写分支：

```text
Crops        作物、基础生长、基础产出、输入和解锁条件
Materials    中间材料、品质、出售价格和加工方式
Recipes      丹药/产品配方、输入、产出、品质和生产时间
Fields       灵田类型、槽位、容量、倍率和维护成本
Upgrades     升级节点、价格、前置和倍率
Skills       技能消耗、冷却、目标、连招标签和效果
Realms       境界门槛、倍率、内容解锁和转世条件
Achievements 成就条件、奖励、隐藏条件和展示文案
Events       事件触发、持续时间、倍率和特殊规则
```

## 4. 生产线主循环

目标版的核心不再是“种一种作物等成熟”，而是把多个生产步骤连接起来。

```mermaid
flowchart TD
    A[选择生产目标] --> B[选择作物/材料来源]
    B --> C{生产线槽位足够?}
    C -- 否 --> D[升级或关闭其它生产线]
    D --> C
    C -- 是 --> E{种子、灵气、肥料和维护成本足够?}
    E -- 否 --> F[购买输入、切换低成本配方或停产]
    F --> E
    E -- 是 --> G[开始生产线]
    G --> H[基础产出 × 多层倍率]
    H --> I{达到收获/加工节点?}
    I -- 否 --> J[继续生产]
    J --> H
    I -- 是 --> K[产出材料或中间产品]
    K --> L{是否进入下一生产线?}
    L -- 是 --> M[自动转移或批量投料]
    M --> H
    L -- 否 --> N[出售、服用、兑换或存入仓库]
    N --> O[获得灵石、修为、转世资源或成就进度]
```

### 多层倍率

```text
总产出倍率 = 基础产出
           × 境界倍率
           × 转世永久倍率
           × 研究/天赋倍率
           × 灵田/生产线倍率
           × 升级倍率
           × 品质倍率
           × 事件倍率
           × 技能连招倍率
```

指数成长的关键不是把一个数字无限加大，而是让每一层都能被玩家理解和追踪：

```text
永久倍率 = PERMANENT_BASE ^ 转世次数
本局倍率 = 境界倍率 × 研究倍率 × 灵田倍率 × 生产线倍率
爆发倍率 = 事件倍率 × 技能连招倍率 × 品质倍率
最终倍率 = 永久倍率 × 本局倍率 × 爆发倍率
```

具体数值使用 `PERMANENT_BASE`、`ASCENSION_REWARD`、`CLICK_YIELD` 等配置项，不把数值散落在按钮回调中。

## 5. 主动操作和技能连招

### 5.1 点击行为

```mermaid
flowchart TD
    A[玩家点击生产目标] --> B{目标正在生产?}
    B -- 否 --> C[提示目标未启动或已完成]
    B -- 是 --> D{点击能量/次数足够?}
    D -- 否 --> E[提示资源不足]
    D -- 是 --> F[立即获得 CLICK_YIELD]
    F --> G[成熟时间减少 CLICK_ACCEL]
    G --> H[连招计数 +1，技能能量增加]
    H --> I{达到批量或连招阈值?}
    I -- 否 --> J[继续生产]
    I -- 是 --> K[开放批量操作或技能窗口]
    K --> L[玩家选择收获、炼制、转化或爆发技能]
    L --> M[结算即时奖励和短时倍率]
    M --> J
```

### 5.2 批量操作

批量操作必须有清晰的收益和成本，不再只是给单次按钮加一个循环：

| 操作 | 作用 | 代价/限制 |
|---|---|---|
| 批量收获 | 一次结算多个已成熟目标 | 消耗批量能量或受到冷却限制 |
| 批量炼制 | 一次处理多份配方 | 需要足够输入和炉容量 |
| 批量出售 | 快速清理库存 | 不能获得额外品质奖励 |
| 批量转化 | 将低阶材料换成高阶材料 | 损耗率或手续费随等级增加 |
| 一键补种 | 自动填充空闲生产线 | 需要种子库存和生产线预算 |

### 5.3 连招结构

具体技能可以继续使用现有技能，也可以扩展成标签化系统：

```text
生长技能 → 收获技能 → 加工技能 → 炼制技能 → 转世爆发技能

例：灵雨诀
  → 聚灵/加速
  → 批量收获
  → 批量炼丹
  → 狂暴/品质提升
  → 在事件结束前结算一轮高倍率产出
```

连招结算需要同时记录：

- 技能顺序是否正确。
- 两次技能之间的最大允许间隔。
- 消耗的灵气、能量和材料。
- 当前目标是否属于同一条生产线。
- 连招倍率、成就进度和失败反馈。

## 6. 境界、转世和飞升

```mermaid
flowchart TD
    A[当前局持续生产] --> B{达到境界门槛?}
    B -- 否 --> A
    B -- 是 --> C[突破境界]
    C --> D[提高本局倍率和寿元上限]
    D --> E[解锁新作物、配方、田、生产线或技能]
    E --> F{达到本境界的终局条件?}
    F -- 否 --> A
    F -- 是 --> G[开放转世/飞升]
    G --> H{玩家确认重置?}
    H -- 否 --> I[继续当前局，冲刺更多成就和资源]
    I --> A
    H -- 是 --> J[统计本局贡献]
    J --> K[发放转世资源和永久奖励]
    K --> L[检查成就、图鉴和隐藏目标]
    L --> M[清空 RunState]
    M --> N[应用 PermanentState 永久倍率]
    N --> O[进入下一挑战层/下一飞升阶段]
    O --> P[重新选择开局路线]
    P --> A
```

### 重置时清空与保留

| 清空的本局状态 | 保留的永久状态 |
|---|---|
| 灵石、灵气、当前修为 | 转世/飞升次数 |
| 当前作物、灵材、丹药 | 永久倍率和永久货币 |
| 当前境界和灵田配置 | 研究树、天赋树和永久解锁 |
| 临时 buff、事件、技能冷却 | 成就、图鉴和最高记录 |
| 本局生产线和库存 | 已领取的里程碑奖励 |

转世奖励不只给一个数字，还要能改变下一局的开局选择：

```text
转世资源 → 永久倍率
          → 开局资源
          → 新生产线
          → 新技能槽
          → 新作物/丹药
          → 新成就分支
```

## 7. 离线结算

```mermaid
flowchart TD
    A[保存退出] --> B[记录 saved_at、生产线、库存和自动化配置]
    B --> C[再次启动]
    C --> D[计算 elapsed]
    D --> E[读取 OFFLINE_EFFICIENCY]
    E --> F[有效时间 = elapsed × OFFLINE_EFFICIENCY]
    F --> G[遍历全部生产线]
    G --> H{输入、容量和维护成本足够?}
    H -- 是 --> I[结算该生产线的生长、收获、加工和转化]
    H -- 否 --> J[该线停产，记录停产原因]
    I --> K{还有生产线?}
    J --> K
    K -- 是 --> G
    K -- 否 --> L[结算自动技能、成就、里程碑和资源汇总]
    L --> M[写入离线报告和新 saved_at]
    M --> N[玩家查看收益并继续当前局]
```

离线结算的规则：

1. 结算所有已开启的生产线，不只结算自动修炼。
2. 生长、收获、加工、炼制和资源转化使用与在线相同的公式。
3. 通过 `OFFLINE_EFFICIENCY` 降低产出效率，目标范围为 0.5~1.0。
4. 输入不足、库存满、生产线停用或维护成本不足时，该线停止，不凭空产出。
5. 离线期间不执行需要玩家选择目标的技能连招；自动技能只执行已经配置的安全策略。
6. 里程碑、成就和转世资源必须与在线结算走同一个奖励入口。

## 8. 成就、里程碑和留存目标

```mermaid
flowchart TD
    A[生产、点击、炼丹、突破、转世或收集行为] --> B[事件记录器]
    B --> C{满足成就条件?}
    C -- 否 --> D[累计进度]
    D --> A
    C -- 是 --> E[标记成就完成]
    E --> F{是否已经领取?}
    F -- 是 --> G[只保留完成记录]
    F -- 否 --> H[发放永久奖励]
    H --> I[解锁新内容、倍率、称号或挑战]
    I --> J[写入永久存档]
```

成就分为几类：

| 类型 | 示例目标 | 奖励方向 |
|---|---|---|
| 产量 | 单局收获 `TARGET_AMOUNT` | 永久生产倍率 |
| 主动 | 连续点击、批量收获或完成连招 | 点击收益、技能槽或能量上限 |
| 生产 | 完成指定配方链 | 新配方、生产线或加工倍率 |
| 境界 | 首次达到指定境界/飞升阶段 | 永久资源或开局加成 |
| 极限 | 在限定时间或低资源下完成目标 | 稀有天赋、称号或特殊内容 |
| 收集 | 解锁作物、丹药、品质和事件图鉴 | 收集倍率或新路线 |

## 9. 成本决策

目标版每条主要操作都要带来“现在收益”和“未来效率”的选择：

```mermaid
flowchart TD
    A[获得一批资源] --> B{直接出售?}
    B -- 是 --> C[立即获得灵石，牺牲后续配方材料]
    B -- 否 --> D{投入低阶生产线?}
    D -- 是 --> E[稳定产出和较低风险]
    D -- 否 --> F[投入高阶生产线]
    F --> G{输入、维护和槽位够吗?}
    G -- 否 --> H[停产或先升级基础设施]
    G -- 是 --> I[高收益但占用更多资源]
    E --> J{保留资源冲刺转世?}
    I --> J
    C --> J
    H --> J
    J -- 是 --> K[放弃短期消费，积累转世贡献]
    J -- 否 --> L[购买升级、技能和批量能力]
    K --> M[转世获得永久倍率]
    L --> A
```

必须进入配置或状态的数据包括：

- 种植/生产输入成本。
- 生产线槽位和维护费用。
- 批量操作能量和冷却。
- 技能消耗、连招失败代价和爆发窗口。
- 高阶配方的库存容量与停产条件。
- 转世前保留比例和转世奖励公式。

## 10. 从当前版本迁移到目标版

```mermaid
flowchart LR
    A[当前 GameState 单体逻辑] --> B[拆出 RunState / PermanentState]
    B --> C[把作物、丹药、升级和技能移入 ContentRegistry]
    C --> D[统一 SimulationEngine 在线结算]
    D --> E[接入点击即时产出、批量操作和连招]
    E --> F[加入转世/飞升结算器]
    F --> G[离线复用同一结算器]
    G --> H[接入成就和图鉴事件记录]
    H --> I[扩充内容数据，不再扩张按钮分支]
```

建议的模块接口保持少而深：

```text
SimulationEngine.tick(delta, RunState, PermanentState, ContentRegistry)
SimulationEngine.apply_action(action, RunState, PermanentState, ContentRegistry)
SimulationEngine.simulate_offline(elapsed, snapshot, ContentRegistry)
AscensionEngine.preview(RunState, PermanentState, ContentRegistry)
AscensionEngine.commit(RunState, PermanentState, ContentRegistry)
AchievementEngine.record(event, PermanentState, ContentRegistry)
```

按钮只提交动作，不直接修改资源；在线、离线、测试和转世预览都经过同一套结算入口。

## 11. 目标版验收顺序

1. 一局内可以同时运行多条生产线，并且输入不足时会停产。
2. 点击能立即获得可见收益，不再只是减少一秒倒计时。
3. 批量收获、批量炼制和至少一条技能连招可以完整结算。
4. 境界突破能打开新的内容层，达到终局后可以主动转世/飞升。
5. 转世后本局资源清空，但永久倍率、研究、成就和图鉴仍然存在。
6. 离线结算能处理全部已开启生产线，且输入不足时不会凭空产出。
7. 成就、里程碑和转世奖励都能写入永久存档，并在下一局生效。
8. 新增内容只需添加数据，不需要在 `GameState` 和每个面板里复制一套分支。
