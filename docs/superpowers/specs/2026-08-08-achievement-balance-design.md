# 成就化平衡重构设计记录（2026-08-08）

## 背景

针对 Steam 增量游戏差距分析后，围绕「天赋点 = 多成就来源」重构长期成长：寿元衰减过紧导致零天赋玩家无法完成凡人→炼气循环、天赋点来源单一（突破+里程碑+商店）、离线结算与时长挂钩却只结算自动修炼、炼丹退出主循环后留下空壳。

## 确认的设计决策

### 1. 寿元衰减

- `LIFESPAN_DECAY_PER_SECOND: 2.0 → 0.5` 年/秒。
- 依据：探针实测零天赋凡人→炼气需 84 秒，而 2.0 衰减下凡人仅 30 秒寿命，必然卡死。0.5 后凡人 120 秒、炼气 240 秒、筑基 400 秒、金丹 1000 秒，循环成立且保留压力。

### 2. 突破天赋点

- 替换原 `1 + 境界序号`（炼气 2 / 筑基 3 / 金丹 4）为按境界索引表 `[0, 3, 7, 15]`（凡人 0 / 炼气 3 / 筑基 7 / 金丹 15），随突破发放并累计晋级次数。

### 3. 种植熟练度（跨大限、跨新局永久）

- 共享门槛 `[10, 50, 150, 400]`，奖励按灵植定义（每种作物独立累计收获次数）。
- 产量奖励取当前最高档位（1/1/2/3），成熟时间减免取已达档位最大值，天赋点按首次跨门槛逐档累计（1+2+3+5=11 点/作物，共 44 点）。
- 奖励表：聚灵草 -1 秒、凝神花 -2 秒、赤阳果 -5 秒、天道莲 -60 秒。
- 接入点：`harvest_crop` 计数发点；`SimulationSystem.field_result` 应用产量加成；`crop_base_growth_seconds` / `live_crop_growth_seconds` 应用时间减免。

### 4. 成就系统（方案 C：独立类）

- 新建 `AchievementSystem`（静态查询 + 一次性解锁），19 项成就定义在 `BalanceConfig.ACHIEVEMENTS`，共 49 成就点。
- 成就点独立于修为、灵石、天赋点主经济；解锁检查挂在 `GameState.emit_state_changed()` 统一出口，不重复发点；加载时点数按当前定义重算。
- 指标：总收获次数、累计修为、境界、灵田数、单作物熟练度、轮回次数、天赋节点数。

### 5. 离线一次性折算（完全替换离线自动修炼）

- 与离线时长无关，只按长期计数发放尚未领取的差额，防反复开关游戏刷奖。
- 天赋点 = `min(轮回次数,3) + min(floor(晋级次数/2),2) + min(floor(总收获次数/2000),2)`，总上限 7。
- 灵石 = `(轮回次数×50 + 晋级次数×100 + 总收获次数×2) × 当前境界生产倍率`。
- 离线不增加修为和灵气；大限未续命时不发放（预览显示待领差额）；领取账本持久化。

### 6. 炼丹移除 + 狂暴丹进商店

- 炼丹整体删除：`AlchemySystem`、炼丹标签页、`brew_pill`/`consume_pill`、`pills` 存档字段、6 个旧解锁标志、`RECIPES`/品质常量、炼丹模拟矩阵全部移除；天赋树丹道分支保留（已是灵田修为倍率）。
- 狂暴丹（商店商品）：生产 ×3、持续 5 秒，基础价 100 灵石，每次购买后 ×1.5 递进（四舍五入到 10，不设上限）；购买次数跨大限保留、新游戏重置；大限期间不可购买；连买顺延持续时间；HUD 狂暴标签复用。

### 7. 存档升级

- v10 → v11（熟练度/成就/计数/领取账本）→ v12（成就按定义校正）→ v13（删 pills 与旧解锁标志，加 `shop_purchase_counts`）。
- 旧档迁移：晋级计数缺失时按当前境界补基线；成就只接受当前定义 id 并重算点数。

## 落地状态
